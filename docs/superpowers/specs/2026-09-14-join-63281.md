## Intent (from the Brief — do not rewrite)

Three HCOM defects from the same recycle/mail incident (midi request #63281):

1. **Collision false positive on `xd://`.** OMP `write` to `xd://` devices reports
   `status_context=tool:write`, `status_detail=xd://<tool>`; the `--collision` SQL matches
   exact `status_detail` within 30s across instances, so two actors calling
   `send_to_actor` at the same instant fire `COLLISION both edited xd://send_to_actor`.
   Brief fix (quoted): "do not collide when `status_detail` is a scheme-prefixed internal
   URI (`^[a-z][a-z0-9+.-]*://`). Keep colliding on real filesystem paths. Do **not** drop
   `tool:write` from `FILE_WRITE_CONTEXTS` globally."
2. **`hcom stop` deletes the live roster row.** `stop_instance_inner` →
   `finalize_instance_stop` DELETEs the `instances` row even when the OS pid is still
   alive; the live process keeps talking with no roster row, `send_to_actor` bounces
   ("hcom identity not found"), and reclaim via `hcom start --as` first refuses because
   leaked `CLAUDECODE=1` makes native-first `detect_tool` return claude, which
   `ensure_rebind_compatible` rejects against the omp snapshot. Brief fixes (quoted):
   - 2a: "if the OS pid is still alive, do not DELETE — mark stopped/inactive, keep the
     row, keep session_id. Headless/background kill-the-process path may still delete. Do
     not change `hcom kill`."
   - 2b: "Prefer snapshot tool / `HCOM_TOOL` over leaked native markers on the `--as`
     reclaim path only." Native-first detection stays correct for a *new* session.
   - 2c: "if omp hooks (`omp-start` / `omp-status` / `reportStatus`) run as a named
     instance whose `instances` row is gone, restore the row from process binding /
     session binding / live fd rather than writing events into a hole… Fail closed if
     live fd disagrees with the name."
3. **Omp PTY inject+enter into a nonempty composer.** The delivery loop can PTY-inject
   text + Enter without an empty-composer check; if the operator is drafting, the draft
   is submitted with hcom text appended. Brief fix (quoted): "If the gate cannot observe
   composer contents, do not inject Enter onto a nonempty line — inject the wake only
   when the input is empty, or skip PTY inject and rely on plugin delivery (omp plugin
   already delivers via `sendUserMessage`)."

Preserve (Brief): real file collisions still fire within 30s; soft-stop (`--soft` / omp
plugin session_shutdown) still keeps the instances row and process binding;
`customType: "hcom-bootstrap"` and `[hcom:<name>]` markers; no writes to
`/home/sf/worlds` main; no bouncing midi/kilo/reko/hera.

## Architecture

Three independent hops, each a single boring seam; no new subsystems.

1. **Collision:** one additional conjunct in the collision SQL excludes scheme-prefixed
   internal URIs. SQLite has no regex; `GLOB '[a-z]*://*'` is the boring equivalent of
   the Brief's `^[a-z][a-z0-9+.-]*://` (GLOB anchors at string start; absolute paths
   start with `/`, Windows drive letters are uppercase and contain no `://`). Because the
   inner `EXISTS` joins on `e.status_detail = events_v.status_detail`, excluding the
   outer value excludes the pair — one conjunct suffices.
2. **Stop/reclaim/heal:**
   - 2a: `stop_instance_inner` gains a keep-row branch — live (pid-alive), non-headless,
     non-placeholder, `tool == "omp"` → delegate to the existing
     `soft_finalize_session(keep_process_binding: true)` and return `Stopped` before any
     delete. Row stays (inactive), `session_id` stays on the row, process binding stays,
     the `life.stopped` snapshot event is logged (feeds reclaim + 2c). Children teardown,
     capability revocation, and row/binding deletion are skipped because the process is
     alive. Headless stops still kill + delete; `hcom kill` untouched; placeholder stops
     untouched.
   - 2b: `start_rebind` computes a `rebind_effective_tool` — precedence `HCOM_TOOL`
     (explicit declaration) → target's recorded tool (live row / stopped snapshot) →
     `ctx.tool` (native-first detection) — and uses it for both the compatibility check
     and the new row's `tool`. New-session detection is untouched.
   - 2c: new `instance_binding::recreate_instance_from_stopped_snapshot(db, name)`
     rebuilds a missing row (status inactive) from the latest `life.stopped` snapshot,
     with a fail-closed live-fd guard (snapshot pid alive but no longer holding the
     snapshot session → refuse). Called from (a) `bind_session_to_process` Path 2 when no
     placeholder row exists — completing that path's documented intent ("recover
     canonical name from life.stopped") instead of returning a rowless name — and (b)
     omp `handle_status` before any status write (missing row → restore → rebind
     session/process; unrestorable → drop the write, return an error JSON, never write
     into a hole). `handle_start` additionally falls back to restore + re-bind when the
     incoming session differs from the snapshot's.
3. **Omp inject:** the OpenCode-mode first-message PTY bootstrap is gated by a named
   predicate `pty_bootstrap_inject_allowed(tool)` that is `false` for `Tool::Omp`. Omp
   delivery becomes plugin-only (notify-server wake → `sendUserMessage`), which the Brief
   explicitly blesses ("omp delivery no longer uses PTY inject+enter at all (plugin path
   sufficient)"). OpenCode/Kilo/Pi bootstrap behavior unchanged — their plugins only take
   over after a session exists, and the Brief scopes the change to omp.

- `src/hooks/common.rs` — `stop_instance_inner`: new keep-row branch (below), reusing

## Data / control flow

**Collision (after):** two `tool:write` status events with `status_detail =
xd://send_to_actor` 1s apart → outer conjunct `NOT GLOB '[a-z]*://*'` excludes both → no
`--collision` match. Two events with `status_detail = /home/sf/workspace/hcom/src/foo.rs`
→ unchanged → match.

**Live stop (after):** `hcom stop midi` (midi = live omp pid) → `stop_instance_inner` →
pidtrack record (unchanged) → keep-row branch → `soft_finalize_session` → row `inactive`,
process binding kept, `life.stopped` snapshot logged → hooks/`send_to_actor` still
resolve `midi`; next `omp-start` rebinds via the existing
`recover_process_binding_for_instance` (row present, inactive, omp).

**Reclaim (after):** `hcom start --as midi` with `CLAUDECODE=1` leaked and
`HCOM_TOOL=omp` (or an omp snapshot) → effective tool omp → check passes → row recreated
as tool omp.

**Self-heal (after):** `omp-status --name midi` with the row missing → restore from
`life.stopped` snapshot (live-fd guard) → rebind session/process → status write lands on
a real row. No snapshot / live-fd contradiction → error JSON, no status event written.

**Omp delivery (after):** pending mail → `notify::wake` → plugin notify server →
`deliverPending` → `sendUserMessage` (idle: `prompt()` path starts the turn). The
delivery loop never PTY-types into omp's composer.

## Error handling

- Collision: none — pure SQL predicate change.
- Keep-row stop: `soft_finalize_session` catches its own errors internally (logs
  `sessionend.soft.life_event_failed`); `stop_instance_inner` returns `Stopped`. If the
  row was already gone, `get_instance_full` → `AlreadyStopped` (unchanged, earlier).
- Reclaim: explicit `HCOM_TOOL` that disagrees with the snapshot still bails
  ("Refusing to reclaim …") — only *leaked native markers* are demoted. Directory
  mismatch check unchanged.
- Self-heal: fail closed. No snapshot → `false`; live pid holds a different session →
  `false` (+ `recreate_stopped.live_session_mismatch` error log); Path 2 returns `None`
  on failed recreation; `handle_status` returns `{"error": …}` (exit 0, per handler
  convention) and skips the write.
- Omp inject: if the plugin is not bound, launch readiness already blocks
  (`launch_ready_on_plugin_bind`), so skipping PTY inject cannot strand a launched omp
  silently; undelivered mail remains pending and is retried by the plugin's reconcile
  loop.

## Testing (behavioral contracts; exact tests live in the plan)

1. Collision SQL: seeded in-memory DB — same `xd://send_to_actor` detail 1s apart across
   two instances → **no** `--collision` rows; same real path → both instances match.
   (Mirrors the existing harness at `filters.rs:771`.)
2. Stop: live omp row (pid = test process, background=0) → `stop_instance` → row still
   `Some`, status `inactive`, `session_id` intact, process binding kept,
   `find_stopped_instance_by_session_id` resolves. Dead-pid omp row → row deleted
   (existing semantics preserved).
3. Reclaim: `rebind_effective_tool` — leaked `CLAUDECODE=1` + `HCOM_TOOL=omp` → omp;
   leaked `CLAUDECODE=1` alone with omp snapshot → omp; explicit `HCOM_TOOL=claude`
   against omp snapshot → claude and `ensure_rebind_compatible` bails; empty metadata →
   falls back to `ctx.tool`.
4. Self-heal: `omp-status` with missing row + stopped snapshot → row restored, status
   lands; `omp-status` with no snapshot → error JSON, no row, no status event;
   `omp-start` with missing row + snapshot session → binds and returns the name with a
   real row.
5. Omp inject: `pty_bootstrap_inject_allowed(Some(Tool::Omp)) == false`, `true` for
   OpenCode/Kilo/Pi/Claude/Gemini; code-level proof that the only omp-reachable
   `inject_text`/`inject_enter` site is gated by it (plugin delivery itself is already
   covered by `src/omp_plugin/hcom.test.ts`, `bun run test:plugin`).

All Rust tests run via `cargo test --bin hcom <filter>` (unit tests live in-module).

## Non-goals

- Changing stop semantics for non-omp tools (their SessionEnd/PTY-exit teardown already
  covers process death; the Brief's defect and test are omp-shaped).
- Changing `hcom kill`, headless stop, or placeholder stop behavior.
- Changing native-first `detect_tool` for new sessions.
- OpenCode/Kilo/Pi first-message bootstrap inject (their plugins require an existing
  session; Brief scopes hop 3 to omp). The unreachable-for-omp `Tool::Omp` arm in the
  active-state-machine text selection (`delivery.rs:1917-1918`) is left as-is.
- `hcom term` explicit operator inject.
- Worlds `clearPaneForResume`, `send_to_actor`, `recycle_actor` (midi's .55/.56/.57).
- Bouncing midi/kilo/reko/hera; writing `/home/sf/worlds` main; External `--from`
  broadcast; participant bootstrap / `--as-system` (already landed).

## Implementation approach chosen (and rejected internals)

- **Collision:** SQL `NOT GLOB '[a-z]*://*'` on the outer clause. Rejected: dropping
  `tool:write` from `FILE_WRITE_CONTEXTS` (Brief forbids — misses real omp repo writes);
  Rust-side post-filtering (would diverge between `events`/`listen`/subscriptions);
  a stricter hand-rolled GLOB for the full regex char class (YAGNI — the loose pattern
  already splits scheme URIs from every real path shape this system emits).
- **2a:** reuse `soft_finalize_session(keep_process_binding: true)` verbatim rather than
  a new bespoke "live-stop" path — it is the proven omp soft-stop and produces exactly
  the Brief's end state (row kept, inactive, session_id kept, process binding kept,
  `life.stopped` snapshot logged for reclaim/self-heal). Scoped to `tool == "omp"` +
  live pid + non-headless + non-placeholder. Rejected: all-tools keep-row (changes
  Claude/Gemini SessionEnd row lifetime — operator-visible and not Brief-decided);
  threading a flag through `finalize_session` (larger diff, same effect).
- **2b:** effective-tool precedence `HCOM_TOOL` → snapshot → detection, computed once in
  `start_rebind` and used for both the guard and the new row. Rejected: changing
  `detect_tool` order globally (Brief: native-first stays for new sessions); refusing
  whenever native markers disagree (that is the bug).
- **2c:** complete the existing Path 2 restore (snapshot-based row recreation) plus a
  restore-before-write guard in omp `handle_status`, instead of a new watcher/reaper.
  Fail-closed live-fd guard mirrors the existing `handle_start` guard
  (`handlers.rs:161-191`) and Path 3 (`instance_binding.rs:611-624`).
- **Hop 3:** skip the omp PTY bootstrap entirely (plugin-only delivery). Rejected:
  scrape-based empty-composer check for omp — impossible, `get_input_box_text` is `None`
  for omp by design (`screen.rs:603`); gating Enter but still injecting (still pollutes
  the operator's draft).
